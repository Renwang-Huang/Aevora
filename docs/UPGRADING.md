# 原生版本升级

当前已实现的便捷入口面向 Linux 用户级服务安装。新版二进制包含 Host、SQLite
和 Console；用户无需重新安装数据库、Node、Python 或 Go。下载与平台构建状态
以实际交付为准。当前没有远程自动发现、自动下载或正式发布的升级源。

从交付包取出匹配平台的二进制，从可信发布清单取得它的 SHA256，在外部终端执行：

```sh
aevora upgrade --project my-project --binary /absolute/new/aevora --sha256 RELEASE_SHA256
```

使用 `connect automatic` 的日常连接保留所属项目的自动接入策略，新客户端会话取得
新版 Host 实测条件和新 Run，无需手动指定日常任务。固定任务入口可重复指定
`--resume-task my-task`，但只有运行条件仍与不可变任务定义一致时才能恢复；版本或
revision 已变化的实测任务应新建。省略时不会恢复历史固定任务授权。
首次从不含 upgrade 的旧版安装升级时，可以用新文件执行同一命令，并加
`--target /absolute/installed/aevora`。升级目标必须是该项目已注册用户服务的程序。

## 一次升级会做什么

1. 将待升级文件放到安装目录的临时文件中，核对显式 pin 后才运行其版本检查。
2. 核对平台、存储 schema 和所属服务；其他项目仍在使用同一程序时要求先停止它们。
3. 在用户私有状态目录保存旧程序和 SQLite 一致性备份，记录升级阶段。
4. 正常停止所属 Host，原子替换程序，保留原 Console 端口并由用户服务管理器启动。
5. 核对实际进程身份、版本、MCP 握手与 Console 健康，重新授权指定的任务。

主机配置、数据库路径、任务定义、模型账户和安全设置保持。登录自启设置保持原样。
当前用户服务未运行时，仅替换程序；此时不能指定需要恢复的任务。前台服务和其他
平台尚未提供该升级流程，应使用所属包管理器或按平台的安装说明升级。

当前 connector 将下游 MCP 会话与 Host 连接分开；同一构建、相同条件的正常 Host
重启后，自动接入可在下一次显式请求前恢复原 Run。业务请求若可能已执行而丢失
响应，会报告结果未知，不自动重放。版本升级改变实测条件时，原会话拒绝暗中改绑，
应重新连接客户端以建立新任务；首次替换已退出的旧 connector 也需要重连一次。
新会话会重新读取工具 schema 和工作流指引。完整行为见[本地任务](LOCAL_WORKFLOW.md)。

## 失败与回退

校验或备份失败时不替换安装程序。停止后的失败会尝试恢复旧程序和所属服务；
`ROLLED_BACK`表示已恢复并完成就绪检查，`RECOVERY_REQUIRED`表示需要查看 receipt
中的实际错误。程序检测到目标被其他操作修改时拒绝覆盖。

数据库不会自动覆盖回备份，避免删除升级期间的历史。回退保持同一存储格式；
不自动跨 schema 迁移或降级。升级 receipt、旧程序和备份保存在
`~/.local/state/aevora/upgrades/`，不要将整个私有状态目录提交或公开归档。

SQLite 物理 schema 相同不保证旧程序认识新的诊断来源格式。版本输出中的
`capture_record_reader` 表示来源读取能力；本版写入带模板/分组身份的来源后，
升级命令会拒绝切换到不声明相应能力的旧二进制。自动回退也做同样核对，无法
安全回退时保留数据库并报告 `RECOVERY_REQUIRED`，不以覆盖数据库恢复旧格式。
首次安装此保护时应使用新二进制执行 upgrade 并明确 `--target` 指向已安装文件；
旧版升级命令没有该逻辑格式检查。手工替换程序同样不能保证兼容。

后续正式发布可复用现有 GoReleaser 交付流程生成固定版本、校验清单和包管理器入口，
让所属包管理器负责下载、版本选择和升级。当前实现没有假定这些远程发布入口已存在。
设计参考 [GoReleaser](https://goreleaser.com/customization/publish/homebrew_casks/)
与 [go-selfupdate](https://github.com/creativeprojects/go-selfupdate) 的固定版本、校验和与替换流程。
