## Q01: bounded indexed recall
Host attested `task.shared_state_kind` determines a material scope partition, declared by the Rule and Experience and verified in the witness. `*` means universal. Missing/unknown partition reads all partitions (can explicitly exceed capacity). Graph query selects committed PUBLIC identities in these partitions with stable id seek pagination, 64 per page, epoch pinned across all pages. Current-scope >256 fails CAPACITY_EXCEEDED; unrelated tenant growth does not consume the candidate budget. It never chooses a caller supplied ID list. Independent reference query enumerates all committed identities and compares eligible scope using raw payloads, not the product discovery function. Partition is a recall dimension, not a strategy prerequisite; other hard premises still yield ABSTAIN.

## Q04/Q10/Q11: complete witness
Publication root declares a bounded, chunkable exact record set of all experience revisions/rules/premises/support/counter/observations/governance and Task/Context/Authority endpoints. Q04 reads real full paths including FOR_TASK and ATTESTED_BY; Q10 bounded id reads verify canonical payload, SHA and every native projection; Q11 enumerates actual incident semantic edges for the declared closure. Exact reached node/edge sets must equal declarations, including negative evidence and published governance. No filtering untrusted authorities out of the returned rows: validator rejects them. Registered ENGINEERING_VERIFIER and INDEPENDENT_ORACLE require Host registry pins to authority and exact result digest; strings alone grant nothing. EXTERNAL_UNVERIFIED is never support.

Root manifest generation is a completeness catalogue, not last-writer-wins rule selection. Explicit SUPERSEDES DAG and committed governance determine effective revisions; all rule alternatives remain visible. Staging is invisible without a matching canonical COMMITS edge. Records and edges of a published closure are immutable; any semantic change requires a newer complete manifest and epoch fence. Out-of-band admin edits are detectable where closure/manifest pins apply but malicious DB administration is outside trust.

## Q08: composed authorization
Host capability first; fixed physical graph; current Session/TenantState plus registered grant generation/TTL/run/session/profile; bounded data retrieval; final graph/permission check; Broker output under owner lock. Every page revalidates current manifest/witness (cache is not truth), semantic/authz epoch and grant generation. HMAC cursor is connection-local and additionally bound to run/session/tenant/profile/query/view/args/documentSHA. Regrant uses new generation; old cursor rejected. Capability revocation and send are serialized by Broker lock. Arbitrary external graph writers are not synchronized with a socket send: a residual check-to-send interval is measured/reported, never claimed atomic across DB and socket. Delivered bytes cannot be recalled.

### Q01 completeness correction from an actual red control
A damaged native scope index projection can omit an entire candidate before its witness is validated. The new real DB negative control reproduced this; the earlier index-only implementation is not accepted as complete. rc2 read-side now requires `TenantState.discovery_heads`: per-scope references and canonical hashes of immutable QuerySnapshot documents with document_kind=DISCOVERY_CATALOGUE. Each actual graph document declares the complete experience→current publication root ID/SHA map for that scope. Q01 still performs native scoped seek discovery, but its complete result set must exactly equal the relevant authenticated graph catalogue. The returned root must match its catalogue pin. Missing candidate, missing COMMIT or stale governance root is GRAPH_INTEGRITY_ERROR; >256 relevant members is explicit CAPACITY_EXCEEDED. Nonrelevant catalogue bodies are not loaded. Every cached bundle/page revalidates the current catalogue as well as the full witness. This reuses bounded graph snapshots; it is neither a model-provided ID whitelist nor an in-memory strategy answer. G22 final state JSON must atomically publish the new affected catalogue head with semantic epoch/COMMITS. Earlier unsealed G21 fixture graphs lacking these heads are not silently upgraded; all final acceptance uses new owned graphs.
