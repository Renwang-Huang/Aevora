# Codex 诊断信号采集

原生 Host 可接收官方 Codex `PostToolUse` hook 的有界诊断信号。`aevora capture hook`
从 stdin 接收一次 hook JSON，只有已登记项目的 Bash 或 apply_patch 输出命中固定诊断
词汇时才写队列：JSON 解码异常、上下文冲突、重连要求、连接拒绝、权限拒绝。
命中只是文本分类，不证明工具失败、根因或结果；第三方程序也可输出这些字符串。

队列只保存版本、已登记项目提示、工具类别、诊断类别、受限格式的 session/turn/tool
调用标识及其组合标识，以便回到原会话核对。**不保存命令、工具输出、用户提示、助手答复、transcript、工作区路径
或模型凭据**；输入最多 256 KiB。完整、可识别的 Aevora 记忆查询结果被跳过，工程命令中的项目名或路径不会触发排除；Aevora 命令的真实诊断仍可采集。其他未知工具、
未登记目录及未命中的输出被跳过。不能声称过滤了任意形式的回声，也不能把这几个
词汇当作完整的任务事件采集。

私有 outbox 最多4096条，写入使用原子替换、同步和并发锁。Host 按项目白名单
核对后将来源记录、按项目提示和信号类别分组的未核验候选及接收结果放入同一 SQLite
事务；只有返回匹配原记录的摘要后才删除
队列文件。提交后响应丢失或 Host 重启时，以不变事件 ID 幂等对账。无权项目、
损坏文件和未确认记录保留，状态可见；轮转扫描避免它们饿死其他项目。

`aevora capture status --project NAME --json`显示当前待处理数量和 Host 最近一次
有界扫描；`invalid_observed` 是该次扫描观察的下界，不能当作全部坏文件统计。
批次上限计算所有尝试读取的文件，包含损坏文件；文件之间检查 100ms 预算，
单次文件系统读取不承诺硬实时超时。游标跨过坏项并在队列末尾轮转。
Host 将扫描位置持久保存；重启从该位置继续，扫描位置不是业务提交或删除确认。
损坏的游标保留，Host 继续内存轮转并报告恢复状态。

`capture status --client-home ABSOLUTE_HOME` 区分配置缺失、自有配置、已修改或无法
读取。handler 另存一个固定类型的最近回调样本，区分无信号、回声、未登记目录、
入队及失败；并发调用按最后一次替换显示，不是完整计数或严格事件顺序。
该样本只证明 handler 收到过输入，不认证 Codex 身份，也不能证明客户端已信任
hook。多个 Codex home 共享 Host 状态，来源尚未按 home 认证；信任状态保持未知。

保留项可用 `capture quarantine --event ID` 预览，加 `--apply` 可逆地移入私有隔离区；
`capture restore --event ID --apply` 恢复，目标已存在则拒绝覆盖。移动不改写内容，
也不授予原来没有的项目权限。`capture reset-cursor --apply` 保留旧游标并重置，
正常 Host 的内存游标在重启后读取该值；损坏游标可在下次扫描恢复。原始事件不删除。
数据来自同用户可发出的 hook 输入，始终是 `EXTERNAL_UNVERIFIED`，不能创建可信
Outcome、证明项目条件或自动发布。采集异常返回不中断工具结果的警告；即使如此，
超过输入上限、hook 未被信任、Host 未运行或磁盘不可用时仍不能声称捕获完整。

新来源按项目提示、session、turn、诊断类别和模板摘要关联到同一草稿，保留每条来源
记录和一个图中来源锚点；不同会话或回合不会因相同词汇永久合并。旧分组保留历史
语义。新事件不会复活已拒绝的同一分组；其他回合的候选独立。按来源记录身份
对账，计数表示已存记录数，不代表独立真实失败或次数；session/turn/tool 标识也是
未核验线索。草稿条件和范围为空，不能直接准入或发布；规则建议只供核实原始结果。

新来源的分组协议和模板内容摘要固定在来源记录中；修改模板文字会创建新的分组，
不会改写旧候选。旧格式来源按历史身份读取，重复投递仍返回最初的归属；升级前
没有候选归属的来源保留为未分组历史，不静默迁移或重写。模板摘要只用于版本身份，
不代表建议已经核验。

Console 的“查看全部来源”和 `capture sources --project NAME --candidate ID`
提供有界只读分页，`--after` 使用返回的 `next_cursor`，每页最多 50 条。按稳定 ID
排序，不是时间顺序；分页过程中新增较小 ID 需要重新从首页读取。接收时间不代表
实际事件发生时间。会话/回合定位只是未核验分组，不证明同一根因、采取的修复、
工具成功或任务完成；没有这些字段时仍保持未知。

按照 [OpenAI Hooks 文档](https://learn.chatgpt.com/docs/hooks)，非托管 hook 的
确切配置需要在 Codex 的 `/hooks` 中由用户审阅和信任；某些工具路径不产生 hook。
可先运行 `aevora capture install --project NAME --json` 查看完整配置，再加 `--apply`
创建当前 `CODEX_HOME` 的 `hooks.json`；已有文件、已被修改的文件和没有归属记录的
文件一律保留并报冲突，不覆盖也不自动接管。`--client-home` 可选择另一个 Codex
配置目录；不同目录均需各自审阅和信任。创建和归属记录之间若异常中断，文件保留
供人工检查，不应删改用户原有内容。要移除完全未修改的自有配置，可运行对应的
`aevora capture remove --project NAME --apply`；定义或归属记录改变时拒绝移除。

`aevora capture hook --session-root ABSOLUTE_ROOT` 是 handler，普通 Host drainer
运行不证明 hook 已经安装、受信任或执行。完整正文提炼、跨会话关联与
真实效用评估仍需后续工作，不能凭分类信号虚构原因或修复方案。
